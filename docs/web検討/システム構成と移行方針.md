## 2. MycalinksPOSを使う利点

### MycalinksPOSとは
株式会社Mycaが提供するカードショップ特化型POSレジシステム。
190,000ユーザー超のカード管理アプリ「Mycalinks」と連携。

### 主な利点

| 利点 | 詳細 |
|------|------|
| **トレカ特化** | シングルカード単品管理、状態別価格設定、低レアまでのマスターデータ配信 |
| **業務効率化** | 新弾登録: 30-40分→10分。在庫登録1/3の時間に短縮 |
| **相場連携** | リアルタイム相場データ。ワンクリックで価格更新&買取表作成 |
| **買取機能** | アプリ連携買取。受付→署名→清算まで一気通貫。導入事例: 買取額3倍 |
| **EC連携** | おちゃのこネット・Shopifyとリアルタイム在庫同期 |
| **Mycalinks Mall** | アプリ内ECモール。追加作業ゼロで出品。19ジャンル対応 |
| **料金定額** | スタッフ数・タイトル数増加で料金変わらず |

### PayPayとの関係

**MycalinksPOS自体にPayPay決済機能は確認されていない。**

PayPay決済は **おちゃのこネット経由** で提供されている:
- おちゃのこネットがPayPayオンライン決済に対応 (2021年3月~)
- 手数料: 3.5～3.6%
- おちゃのこネットの管理画面から設定

つまり決済フローは:
```
顧客 → おちゃのこネット (カート/注文) → PayPayオンライン決済 → 入金
```
MycalinksPOSは在庫管理・価格管理を担い、決済はおちゃのこネットが処理。

## 3. 方式比較: 現状維持 vs Firebase移行

### 方式A: 現状維持 (MycalinksPOS + おちゃのこネット + GAS)

```
MycalinksPOS ←→ おちゃのこネット (EC+決済) ←→ GAS (カスタム機能)
```

| 観点 | 評価 |
|------|------|
| **在庫管理** | MycalinksPOS (POS↔EC自動同期) |
| **EC機能** | おちゃのこネット (カタログ/カート/会員/決済) |
| **決済** | PayPay (おちゃのこネット経由) + クレカ/コンビニ等も設定可能 |
| **カスタム機能** | GAS (バインダー/デッキ屋/バウンティリーグ等) |
| **コスト** | おちゃのこネット月額 + MycalinksPOS月額 |
| **メリット** | ・実績あるエコシステム。カードショップで一般的な組み合わせ |
|              | ・POS↔EC在庫同期が公式サポート |
|              | ・おちゃのこネットに多数の決済オプション |
|              | ・Mycalinks Mall経由の追加集客 |
| **デメリット** | ・GAS依存 (レート制限、デバッグ困難、スケーラビリティ) |
|              | ・カスタム機能の開発/保守が分散 |
|              | ・おちゃのこネットのデザイン/機能制約 |
|              | ・データが複数システムに分散 |

### 方式B: Firebase全面移行

```
MycalinksPOS ←→ Firebase (EC+決済+カスタム全部)
```

| 観点 | 評価 |
|------|------|
| **在庫管理** | Firebase + MycalinksPOS (連携を自前開発) |
| **EC機能** | Firebase Hosting + Firestore (自前構築) |
| **決済** | PayPay Web Payment API or Stripe (自前構築) |
| **カスタム機能** | Cloud Functions + Firestore (統合) |
| **コスト** | Firebase (従量課金) + MycalinksPOS月額 + 開発コスト |
| **メリット** | ・全データ統合 (Firestore一元管理) |
|              | ・自由なUI/UX設計 |
|              | ・リアルタイム更新 (Firestore listeners) |
|              | ・スケーラビリティ |
|              | ・WebRTCバトルとの統合 |
| **デメリット** | ・MycalinksPOS→Firebase連携は公式未サポート (自前開発必要) |
|              | ・決済システム自前構築 (PCI DSS考慮) |
|              | ・おちゃのこネットの既存決済オプションを失う |
|              | ・開発・運用コスト増 |
|              | ・移行リスク (4,253商品 + 会員データ) |

### 方式C: ハイブリッド (推奨)

```
MycalinksPOS ←→ おちゃのこネット (EC/決済は現状維持)
                      +
                Firebase (カスタム機能のみ移行)
```

| 観点 | 評価 |
|------|------|
| **在庫管理** | MycalinksPOS ←→ おちゃのこネット (現状維持) |
| **EC機能** | おちゃのこネット (現状維持) |
| **決済** | PayPay (おちゃのこネット経由、現状維持) |
| **カスタム機能** | **GAS → Firebase Cloud Functions + Firestore** |
| **コスト** | 現状 + Firebase無料枠 (Spark plan) |
| **メリット** | ・在庫/EC/決済の安定運用を維持 |
|              | ・GAS依存を段階的に解消 |
|              | ・リスク最小 (段階的移行) |
|              | ・カスタム機能のパフォーマンス向上 |
|              | ・将来のEC全面移行への準備 |
| **デメリット** | ・システムが2つに分散 (おちゃのこ + Firebase) |
|              | ・将来的にはEC部分も移行が必要 |

## 4. おちゃのこネットの決済対応 (参考)

現在PayPayのみ利用中だが、おちゃのこネットは以下に対応:

| 決済方法 | 手数料 | 決済代行 |
|---------|--------|---------|
| クレジットカード | 3.5～5.0% | ゼウス/イプシロン/GMO/SB等 |
| PayPayオンライン | 3.5～3.6% | おちゃのこネット標準 |
| Amazon Pay | 3.9% | Amazon |
| 楽天ペイ | 4.0% | 楽天 |
| コンビニ払い | 120円～/件 | ゼウス/イプシロン |
| 銀行振込 | 設定のみ | - |
| 代金引換 | 決済代行経由 | イプシロン/ゼウス |
| 後払い | 3.5～5.0% | 複数対応 |
| キャリア決済 | +0.5% | 各社 |
| PayPal | 3.6% | PayPal |

※PayPay以外の決済を追加する場合、おちゃのこネット管理画面から設定可能。

## 5. 推奨移行ロードマップ

### Phase 1: バウンティリーグ移行 (今回のスコープ)

**GAS #4 → Firebase Cloud Functions + Firestore**

- オンライン手配書 (Users/Attacks/History) → Firestore
- 9 API actions → Cloud Functions
- /page/wanted → Firebase Hosting

**EC/決済/在庫は変更なし**

### Phase 2: 他のGAS機能の移行

- GAS #1 (コード検証) → Firestore
- GAS #2 (ヤバイデッキ屋) → Firestore
- GAS #3 (クラウドバックアップ) → Firestore
- GAS #5 (WEBストレージ) → Firestore

### Phase 3: EC機能のFirebase化 (将来)

- おちゃのこネットAPI経由で商品データ取得 → Firestore
- 自社ECフロントエンド構築 (Firebase Hosting)
- 決済: Stripe (PayPay/クレカ/コンビニ対応) or PayPay直接API
- MycalinksPOS連携: おちゃのこネットAPI or 直接連携

### Phase 4: 在庫管理統合 (最終目標)

- MycalinksPOS ←→ Firestore 直接連携
- リアルタイム在庫ダッシュボード
- 実店舗/EC/Mycalinks Mall統合在庫
- おちゃのこネット完全脱却

## 7. スプレッドシート構造

### 「オンライン手配書」(1hgd2VZFFCgVgr7WMOA6MPqdTiOogyCq2xFnppkLP4xI)

**Usersシート:**
userId | password | displayName | coins | monthlyCoins | todayCoins | idNumber | lastMonth | lastDay | customPoster

**Attacksシート:**
attackerId | targetIdNumber | startTime | endTime | status

**Historyシート:**
timestamp | oderId | opponent | result | bonus | coins

### 「アイランド」(1i0ZKmzyePKwiK2iYjiGm86bNJITt3OC6ijL96njaW6Y)

**usersシート:** userId | password | displayName | createdAt
**Islandsシート:** islandId | status | waitingUser | currentBattleId | updatedAt
**Codesシート:** code | status | usedBy | usedAt
**Battlesシート:** battleId | islandId | creatorId | joinerId | status | createdAt | endedAt
**Signalingシート:** battleId | type | sdp | fromUserId | createdAt
**IceCandidatesシート:** battleId | candidate | sdpMid | sdpMLineIndex | fromUserId | createdAt
